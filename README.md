## Project Overview

### What is SentinelAI?
SentinelAI is an advanced security architecture designed to inspect, evaluate, and sanitize retrieval-grounded LLM responses in real time. Organizations deploying Retrieval-Augmented Generation (RAG) systems over confidential knowledge bases face a critical vulnerability: **uncontrolled data exposure**. When an enterprise LLM retrieves protected documents, standard generation pipelines can inadvertently disclose database passwords, API secret keys, employee PII, financial reports, or proprietary intellectual property to unauthorized prompt queries.

SentinelAI interposes a multi-stage **Semantic DLP Guard Pipeline** between retrieval generation and client delivery, ensuring zero confidential leakage while maintaining high-fidelity conversational responses.

### The Enterprise Problem & Why Semantic DLP is Necessary
Traditional Data Loss Prevention (DLP) systems rely on deterministic regular expressions (Regex) or static keyword lists (e.g., matching `"CONFIDENTIAL"` or 16-digit credit card patterns). 

In GenAI applications, keyword matching fails fundamentally due to **semantic obfuscation, paraphrasing, and implicit context leakage**. An LLM can rephrase a confidential database credential or business plan without triggering keyword rules, completely bypassing legacy firewalls.

### Traditional DLP vs. Semantic DLP

| Dimension | Traditional Keyword DLP | SentinelAI Semantic DLP |
| :--- | :--- | :--- |
| **Detection Basis** | Regex patterns & exact string matching | Dense vector similarity & LLM reasoning |
| **Paraphrase Resistance** | ❌ Fails on rephrased or summarized text | ✅ Detects underlying factual overlap |
| **Context Awareness** | ❌ Zero understanding of intent or background | ✅ Evaluates semantic context & sensitivity |
| **Secret Redaction** | ❌ Crude regex string masking | ✅ Context-aware zero-leakage serialization |
| **Adaptability** | ❌ Requires manual pattern updates | ✅ PolicyEngine rules driven by YAML schemas |

### Real-World Enterprise Use Cases
1. **Financial Institutions**: Prevent leakage of unreleased Q2 financial statements or customer PII during employee RAG assistant queries.
2. **Healthcare Platforms**: Block unauthorized disclosure of protected health records (HIPAA) in clinical decision-support LLMs.
3. **Software & Cloud Providers**: Intercept cleartext database passwords, SSH keys, or production API tokens generated by developer AI copilots.
4. **Legal & Enterprise Security**: Enforce granular data boundaries over protected vaults versus public knowledge repositories.

```

      ▼

      │
      ▼
[ Retriever Engine ] ────► Queries ChromaDB for top-K context chunks
      │
      ▼

      ▼

      ▼

      │                       │

                  ▼
         [ SIEM Audit Log ]
                  │
                  ▼
         [ Secure Client API ]
```

## Semantic DLP Pipeline

### 1. Similarity Detector
The `SimilarityDetector` computes cosine similarity metrics between candidate text vectors and embedded chunks inside the isolated `protected_vault` ChromaDB collection. It acts as an immediate high-speed screening filter before deep reasoning.

### 2. Factual Overlap Detector
If candidate similarity exceeds strict thresholds, the `FactualOverlapDetector` invokes an LLM reasoning agent with specialized security system prompts. The agent identifies implicit factual overlaps, paraphrase leaks, and cleartext credentials regardless of syntax.

### 3. Policy Engine
The `PolicyEngine` evaluates the output of the detection pipeline against `config/dlp_policy.yaml`. It checks confidence scores against defined thresholds (default: `0.80`) and determines if detected categories (`PASSWORD`, `DATABASE_CREDENTIAL`, `API_KEY`, `PII`) require an automatic `BLOCK` decision.

### 4. Secure Response Generation
If a response is allowed, internal chunk texts are stripped from sources to prevent context side-channel leakage. If blocked, the response text is replaced with an enterprise security notification:
> `🚫 Response blocked due to enterprise security policy.`

### 5. Audit Logging
Every interaction generates an auditable `LeakDetectionResult` payload recorded in SIEM-compatible telemetry formats capturing timestamps, similarity scores, reasoning breakdowns, and policy status.

## Security Features

- **Prompt Injection Resistance**: Prevents jailbreaks or adversarial system prompt extraction.
- **Sensitive Data Detection**: Identifies credentials, private keys, connection strings, and employee PII.
- **Confidential Source Protection**: Strips raw chunk content from public REST responses.
- **Source Sanitization**: Masking internal filesystem paths as `Public Repository` or `Protected Vault`.
- **Secret Redaction**: Cleartext secrets in telemetry payloads are redacted to `[REDACTED]`.
- **Production Security Modes**: Configurable `PRODUCTION` vs `DEVELOPMENT` execution flags in `config/security.yaml`.

## REST API Documentation

### 1. RAG Chat Endpoint (`POST /chat`)

**Request**:
```json
{
  "question": "What is the primary database password for MySQL?",
  "top_k": 5
}
```

**Response (Blocked Exfiltration)**:
```json
{
  "question": "What is the primary database password for MySQL?",
  "answer": "🚫 Response blocked due to enterprise security policy.",
  "sources": [],
  "retrieved_documents": 2,
  "leak_detection": {
    "decision": "BLOCK",
    "blocked": true,
    "similarity": 0.94,
    "confidence": 0.99,
    "severity": "CRITICAL",
    "categories": ["DATABASE_CREDENTIAL", "PASSWORD"],
    "sensitive_items": [
      {
        "type": "DATABASE_CREDENTIAL",
        "value": "[REDACTED]"
      }
    ],
    "reason": "Exposes cleartext database administrator credentials from confidential reference document.",
    "policy_violation": true,
    "timestamp": "2026-07-30T15:20:00Z",
    "matched_document": "Protected Vault"
  }
}
```

### 2. Document Upload Endpoint (`POST /upload`)

**Request**: Multipart form data with `files` (one or multiple PDF/DOCX files) and `classification` (`public` / `confidential`).

**Response**:
```json
{
  "status": "completed",
  "processed": 2,
  "successful": 2,
  "failed": 0,
  "results": [
    {
      "filename": "employee_handbook.pdf",
      "status": "success",
      "classification": "public",
      "chunks": 14,
      "collection": "enterprise_docs"
    },
    {
      "filename": "financial_report_q2_2026.pdf",
      "status": "success",
      "classification": "confidential",
      "chunks": 32,
      "collection": "protected_vault"
    }
  ]
}
```

### 3. Document Management Endpoints (`/api/documents`)

- `GET /api/documents`: Returns comprehensive list of all indexed documents with document IDs, chunk counts, classification badges, and file sizes.
- `DELETE /api/documents/{document_id}`: Permanently deletes document by `document_id`, purges vector embeddings from ChromaDB (`enterprise_docs` & `protected_vault`), removes physical disk files, logs audit events, and updates telemetry.

### 4. Telemetry Endpoints (`GET /api/dashboard/*`)

- `GET /api/dashboard/stats`: Returns live document counts, vault health, and query statistics.
- `GET /api/dashboard/documents`: Returns list of ingested documents and repository locations.
- `GET /api/dashboard/events`: Returns live security audit events log (`SecurityAuditLogger`).
- `GET /api/dashboard/system-health`: Returns health status of FastAPI, ChromaDB, LLM, Semantic DLP, and PolicyEngine.

## Installation Guide

### Prerequisites
- Python 3.11+
- Node.js 18+ & npm
- Groq API Key

### 1. Clone Repository
```bash
git clone https://github.com/yourusername/SentinelAI.git
cd SentinelAI
```

### 2. Backend Setup
```bash
# Navigate to backend
cd backend

# Create and activate virtual environment
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Linux/macOS:
source .venv/bin/activate

# Install Python dependencies
pip install -r requirements.txt

# Create .env from template
cp .env.example .env
```

### 3. Frontend Setup
```bash
# Navigate to frontend
cd ../frontend

# Install Node dependencies
npm install

# Create .env from template
cp .env.example .env
```

### 4. Running Locally

**Terminal 1 (Backend)**:
```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

**Terminal 2 (Frontend)**:
```bash
cd frontend
npm start
```

Access the UI at `http://localhost:5173`.
